# 4090 服务器部署指南（Ubuntu 22.04 → 跑起来）

> **目标**：在 4090 上装好软件、部署本项目、启动服务。
> **环境**：Ubuntu 22.04 LTS ｜ NVIDIA RTX 4090 24GB ｜ 与机器人同一局域网
> **基于**：`xiaozhi-esp32-server` **v0.9.7**（tag 版，目录名即版本）+ `suiyue/` 大脑
>
> **本文是"照着敲就能跑"的操作序列**；每段的**为什么**见括号注释或
> `docs/部署手册-4090与Pepper联调.md`。命令已对齐 v0.9.7 真实配置行号。

---

## 第0 步 · 系统基线与驱动

```bash
# 确认系统与资源
uname -a                 # Linux ... 5.15.0-*（22.04）
lsb_release -a
nvidia-smi               # ★ 确认 4090 在位、驱动正常、CUDA 版本
free -h                  # 建议 ≥ 16GB
df -h /                  # 建议 ≥ 100GB（权重 + 镜像很占）

# 驱动（若 nvidia-smi 不认卡）
sudo ubuntu-drivers autoinstall
sudo reboot

# NVIDIA 容器工具（跑 docker 时必需）
sudo apt install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker
# 验证 GPU 容器可用（镜像需现场替换为自己的）
sudo docker run --rm --gpus all nvidia/cuda:12.4.0-base-ubuntu22.04 nvidia-smi
```

> ⚠️ **不要装 CUDA Toolkit**。驱动自带 CUDA runtime，PyTorch 用 pip 版即可。
> 装了反而容易和 pip 版 torch 的 cu12x 冲突。

- [ ] `nvidia-smi` 能看到 4090 与显存总量（约 24576 MiB）
- [ ] 记下 `nvidia-smi` 的 **CUDA Version**（决定后面 torch 的 index-url）

## 第 1 步 · 基础软件

```bash
sudo apt update && sudo apt -y upgrade

sudo apt -y install \
  python3.10 python3.10-venv python3.10-dev python3-pip \
  git wget curl unzip vim htop \
  build-essential cmake pkg-config \
  ffmpeg sox libsox-dev libopus0 \
  net-tools openssh-server

# Docker（可选，若想用容器跑 server）
sudo apt -y install docker.io docker-compose-v2
sudo systemctl enable --now docker
sudo usermod -aG docker $USER      # 需重新登录生效

# 防火墙
sudo ufw allow 22/tcp 8000/tcp 8003/tcp 9880/tcp 11434/tcp
sudo ufw enable
```

| 端口 | 用途 | 谁访问 |
|---|---|---|
| 8000 | xiaozhi **WS**（语音/意图双向） | Pepper 网关机 |
| 8003 | **OTA** HTTP | Pepper 网关机 |
| 9880 | GPT-SoVITS API | server 内部 |
| 11434 | Ollama API | server 内部 |

> ⚠️ **内网代理坑（本项目真实踩过）**：`websockets>=14` 的 `connect()` **默认读
> `http_proxy`**。若 4090 设了代理，连内网会失败。
> 在部署前执行：`export no_proxy=127.0.0.1,localhost,192.168.31.*`
> 并写进 `~/.bashrc`。代码侧已用 `proxy=None` 兜底，但仍建议设。

## 第 2 步 · LLM 后端（Ollama）

```bash
curl -fsSL https://ollama.com/install.sh | sh
sudo systemctl enable ollama

# ★关键：告诉 systemd 模型存在哪（否则离线环境下 ollama 找不到模型）
sudo systemctl edit ollama
# 写入以下内容后 daemon-reload + restart：
#   [Service]
#   Environment="OLLAMA_MODELS=/opt/models/ollama"

sudo systemctl daemon-reload && sudo systemctl restart ollama

ollama pull qwen3:8b                       # 主力（ADR-011 决策 2：8B Q4 ≈ 5-6GB 显存）
curl -s http://127.0.0.1:11434/api/tags    # API 探活
ollama run qwen3:8b "只回答四个字：岁悦就位"   # 验证
nvidia-smi                                  # 应看到 ~5-6GB 显存占用
```

> 🔴 **显存硬纪律（ADR-011）**：**禁止用 transformers FP16 加载 8B**（16GB，单卡即满）。
> 一律走Ollama / vLLM 的**量化**版本。

## 第 5 步 · Python 依赖

```bash
# ---- A. 对话引擎 ----
cd /opt/xiaozhi-esp32-server/main/xiaozhi-server
python3.10 -m venv /opt/venvs/xiaozhi-server
source /opt/venvs/xiaozhi-server/bin/activate
pip install -U pip setuptools wheel

# ★ PyTorch 单独装，按你的 CUDA 版本选 index（例：CUDA 12.4 → cu124）
pip install torch==2.2.2 torchaudio==2.2.2 --index-url https://download.pytorch.org/whl/cu124
pip install numpy==1.26.4                    # ★ 必须锁，见下

# ★ 装 torch 后务必锁 numpy —— transformers/torch 2.2.2 与高版本 numpy 有ABI 冲突
pip install numpy==1.26.4
pip install -r requirements.txt
pip check                                    # ★ 检查依赖冲突（会报错就修，别忽略）
```

> ⚠️ **两个真实的坑**：
> 1. `requirements.txt` 头部明确写着「**推荐 python3.10**，以下暂时不推荐升级」。
>    用 3.11/3.12 很可能装不上或跑不起来。
> 2. `numpy==1.26.4` 被夹在注释里写明"不推荐升级"（torch 2.2.2 与高版本 numpy 有 ABI 问题）。
>    **pip 装 torch 时会把 numpy 升到 2.x**，务必再 `pip install numpy==1.26.4` 拉回来。
> 3. `requirements.txt` 有 **41 个包**（含 funasr / modelscope / sherpa_onnx / mem0ai），
>    **首次安装 30–60 分钟**，属正常。

cd /opt/suiyue
python3.10 -m venv /opt/venvs/suiyue-brain      # 或直接用系统 python3
source /opt/venvs/suiyue-brain/bin/activate
pip install -r requirements-dev.txt
# 大脑侧依赖极轻：websockets / PyYAML / websocket-client（3个包）

## 第 7 步 · 改配置为全离线

编辑 `/opt/xiaozhi-esp32-server/main/xiaozhi-server/config.yaml`（**行号为v0.9.7**）：

### 7.1 必改 6 处

| 行号 | 配置项 | 改成 | 为什么 |
|---|---|---|---|
| **L239** | `selected_module.LLM` | `OllamaLLM` | 默认 `ChatGLMLLM` 走智谱 API，**联网** |
| **L243** | `selected_module.TTS` | `GPT_SOVITS_V3` | 默认 `EdgeTTS` **走微软服务器，联网**（头号必改） |
| **L667** | `LLM.OllamaLLM.model_name` | `qwen3:8b` | 🔴 **默认值是 `qwen2.5`，不改会拉错模型** |
| **L956** | `TTS.GPT_SOVITS_V3.refer_wav_path` | 你自己的老人音色音频 | 默认 `caixukun.wav` 是上游示例音 |
| **L963** | `GPT_SOVITS_V3.speed` | `1.0` → 老人场景建议 `0.9` | 语速（非必须） |

**禁用联网插件（L281-L289）** —— 这几行是列表项，**注释掉整行**（行首加 `# `）：

```yaml
  functions:
    - change_role
#   - web_search                  # 联网搜索 ← 注释掉
#   - get_weather                 # ← 注释掉
#   - get_news_from_newsnow       # ← 注释掉
    - play_music
```

> ⚠️ **别把列表删空**——`change_role`（角色切换）和 `play_music`（音乐播放）是
> **server 自带的本地插件**（见 L278 注释），保留即可，不联网。

> 🔴 **L667 是最容易漏的坑**。`OllamaLLM` 默认写死 `model_name: qwen2.5`，
> 而我们离线备的是 `qwen3:8b`。不改的话 server 会去找一个不存在的模型，
> 表现为 LLM 无响应或反复重连，**但不报明确的错**。

### 7.2 确认 3 处不需改（上游已内置）

| 配置 | 行号 | 结论 |
|---|---|---|
| `LLM.OllamaLLM.type: ollama` + `base_url: http://localhost:11434` | L664/L666/L668 | 已内置，只需改 `model_name` |
| `ASR.FunASR.model_dir` | L361 | 本地已满足 |
| `VAD.SileroVAD.model_dir` | L610 | 本地已满足 |

### 7.3 校验

```bash
cd /opt/xiaozhi-esp32-server/main/xiaozhi-server
python3 -c "import yaml; yaml.safe_load(open('config.yaml', encoding='utf-8')); print('YAML OK')"
```

## 第 8 步 · 放置 overlay（3 处薄改动）

> ⚠️ **两个脚本各管一半，注入器必须手动拷** ——
> `apply_overlay_x1x2.py` 只改 `config.yaml` + `mcp_server_settings.json`；
> `apply_overlay_x3.py` **只改 `connection.py`，不拷贝注入器**。
> 漏拷这步**不会报错**（import 有 try/except），但**场景包永远不会被注入**。

```bash
# 1) 先拷注入器（务必用最新，含情绪表达增强）
cp /opt/suiyue/overlay/suiyue_scene.py \
   /opt/xiaozhi-esp32-server/main/xiaozhi-server/core/suiyue_scene.py

# 2) 跑幂等脚本（自带 *.suiyue.bak 备份，可回滚）
cd /opt/suiyue
python3 tools/apply_overlay_x1x2.py /opt/xiaozhi-esp32-server
python3 tools/apply_overlay_x3.py  /opt/xiaozhi-esp32-server

# 3) 验证三处都在位
SD=/opt/xiaozhi-esp32-server/main/xiaozhi-server
grep -n "suiyue" $SD/config.yaml | head -5
grep -n "suiyue-brain" $SD/mcp_server_settings.json
grep -n "suiyue_scene" $SD/core/connection.py
ls -l $SD/core/suiyue_scene.py
```

| | 文件 | 改什么 | 回滚 |
|---|---|---|---|
| **X1** | `config.yaml` | 加 `suiyue.device_id: pepper-01`（**须与大脑 `config.yaml` 字面一致**） | 删该段 |
| **X2** | `mcp_server_settings.json` | `mcpServers` 注册 `suiyue-brain`（stdio） | 删条目 |
| **X3** | `core/connection.py` | `_init_prompt_enhancement()` 注入场景包（2 处约 8 行） | `cp *.bak` |

> ⚠️ **X2 部署时最容易错**：`mcp_server_settings.json` 里的 `command` / `args`
> 是**部署机路径**，示例里可能是 Windows 路径。要改成：
> ```json
> "command": "/opt/venvs/xiaozhi-server/bin/python3",
> "args": ["-m", "brain.mcp", "--config", "/opt/suiyue/brain/mcp/config.yaml"],
> "env": {"PYTHONPATH": "/opt/suiyue"}
> ```
> 用**绝对路径**避免 stdio 子进程因 PATH 找不到解释器而**静默启动失败**。

### 11.2 后台常驻（systemd，推荐）

```bash
sudo tee /etc/systemd/system/xiaozhi-server.service >/dev/null <<'EOF'
[Unit]
Description=SuiYue Xiaozhi Server
After=network.target ollama.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/xiaozhi-esp32-server/main/xiaozhi-server
Environment="PATH=/opt/venvs/xiaozhi-server/bin:$PATH"
Environment="no_proxy=127.0.0.1,localhost,192.168.31.*"
ExecStart=/opt/venvs/xiaozhi-server/bin/python3 app.py
Restart=always
RestartSec=10
StandardOutput=append:/var/log/xiaozhi-server.log
StandardError=append:/var/log/xiaozhi-server.log

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now xiaozhi-server
sudo systemctl status xiaozhi-server
sudo journalctl -u xiaozhi-server -f     # 看实时日志
```

## 排障速查

| 现象 | 最可能原因 | 处置 |
|---|---|---|
| `nvidia-smi` 不认卡 | 驱动未装/未重启 | `ubuntu-drivers autoinstall` + reboot |
| torch 装不上或 import 报错 | CUDA 版本与 index 不匹配 | 按 `nvidia-smi` 的 CUDA Version 换 cu118/cu121/cu124 |
| `numpy` 相关 ABI 报错 | pip 装 torch 时把 numpy 升到 2.x | `pip install numpy==1.26.4` |

## 性能优化（强烈建议做）

首次 stdio 调大脑 MCP 约**13 秒**（拉子进程 + 加载场景包 + 大亮连接超时重试）。
会话建立时同步等 13 秒不可接受。解法：**server 启动时后台预热**。

编辑 `/opt/xiaozhi-esp32-server/main/xiaozhi-server/core/suiyue_scene.py` 已有
`warmup()` 函数，在 `app.py` 启动处调用：

```python
import threading
from core.suiyue_scene import warmup
threading.Thread(target=warmup, args=(config,), daemon=True).start()
```

效果：首个真实会话走缓存，**约 0.000 秒**返回。
