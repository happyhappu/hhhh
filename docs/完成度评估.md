## 4. Pepper 线 G3 / G4 / G7–G10 详解

> 背景：Pepper 端侧代码**已写完并通过编译/单测**，但这些点要么"跨组件契约未定"、要么"必须上真机才能拍板"。

### ~~G3~~ — emotion 信号契约（跨组件）✅ **2026-10-06 已确诊并修复**
- **原判断（已推翻）**：以为"待联调确认 server 实际下发字段结构"。
- **实测结论（v0.9.7 源码核实）**：`core/utils/textUtils.py:84 get_emotion()` 的机制是
  **在 LLM 回复文本里扫描第一个 emoji**，用 `EMOJI_MAP`（L8-30，**21 个标签**）翻成标签，
  下发 `{"type":"llm","text":emoji,"emotion":<tag>}`。字段结构没问题，**问题在标签集**。
- **🔴 确诊的 bug**：云端 21 个标签（funny/crying/angry/sad/loving/surprised/shocked/
  thinking/relaxed/sleepy/silly/confused/neutral/happy/laughing/embarrassed/winking/
  cool/delicious/kissy/confident）与端侧 `EMOTION_TO_ACTION` 的 6 个键
  （happy/excited/soothing/curious/concerned/neutral）**几乎零交集**——只有 `happy`、`neutral`侥幸相同。
  `excited`/`soothing`/`curious`/`concerned` 在 `EMOJI_MAP` 里**根本不存在**。
- **后果**：`gateway.py::_emote_from_emotion` 查表未命中 → 静默回落到 `("posture",{"name":"Stand"})`
  → **Pepper 永远站着不动，不报错、零日志**。这正是"最难查"的一类故障。
- **修法**（`pepper/gateway_config.py`）：新增 `SERVER_EMOTION_TO_SUYUE` 翻译表（21 → 6）
  + `to_suiyue_emotion()`；`gateway.py` 先翻译再查表，且**未收录标签打 WARNING**（不再静默）。
- **守护**：`pepper/test_emotion_contract.py`（9 用例）—— 钉死"翻译结果必须是可执行动作的键"、
  21 个标签全覆盖、6 个动作无死路、跨仓校验 `pepper_v1.yaml` 键集一致。
  ⚠️ 该测试当场抓出我自己的疏漏：`excited` 一度无任何云端标签可达（死动作），已修。
- **联动修正**：`emotion_calibration` 里端侧动作名（`approach_and_wave` 等）不受影响，
  但**云端 LLM 若不知道该输出什么 emoji，就永远触发不了对应动作**——
  故场景包 prompt 需明确"用 emoji 表达情绪"（已列入 X3 后续增强项）。
