# ADR-011 全离线部署基线（air-gapped）

日期：2026-09-07 ｜ 状态：已接受 ｜ **修正 ADR-005 的算力假设（30B 路由不成立）**

## 事实

- 自有算力：**单台 4090（24GB）**，无第二张卡；
- 用户要求：**整个系统不联网也能工作**（老人隐私 + 教学现场网络不可靠 + 无 API 费用）；
- `xiaozhi-esp32-server` 各模块后端可插拔，本地后端齐全（MIT fork，见 ADR-003）；
- `chassis-gateway` 是纯网络协议翻译层（asyncio + websockets，<100MB 内存，ADR-009）。

## 决策 1：所有 AI 模块强制本地后端

| 模块 | 上游联网默认 | **离线基线** | 备注 |
|---|---|---|---|
| VAD | SileroVAD（本地） | 不变 | 可 CPU |
| ASR | FunASR（本地）/ 各云 API | **FunASR SenseVoiceSmall** | 备选 sherpa-onnx 流式 paraformer，更轻 |
| LLM | 智谱 / 豆包 / 阿里 API | **Ollama 或 vLLM → Qwen3-8B Q4** | 单一进程统一管显存 |
| TTS | **EdgeTTS（微软，联网）** | **GPT-SoVITS V3 / Index-TTS / FishSpeech** | 头号必改项，见 §决策 4 |
| 声纹 | 3D-Speaker（本地） | 不变 | |
| 记忆 | mem0ai（云） | **`mem_local_short`** 或 mem0 本地模式 | |
| Intent | function_call | 不变（本地 LLM 承担） | |
| 知识库 | RAGFlow（云） | **禁用** 或本地向量库 | 本期不用 |

**部署形态固定为 server-only**（`.config.yaml` 文件配置、无数据库、2–4GB RAM）。全模块版（MySQL/Redis/智控台）只在需要多用户管理时才上。

## 决策 2：24GB 显存预算 —— 30B 路由降级为 14B

| 模块 | 选型 | 常驻显存 |
|---|---|---|
| LLM 主力 | Qwen3-8B Q4_K_M（Ollama）/ AWQ（vLLM） | 5–6 GB |
| LLM 高价值 | Qwen3-14B Q4（按需加载） | ~9 GB |
| ASR | FunASR SenseVoiceSmall | ~1.5 GB |
| TTS | GPT-SoVITS V3 | ~2.5 GB |
| Embedding | bge-small-zh-v1.5（**CPU**） | ~0.2 GB |
| **常驻合计** | | **约 9.5–11 GB**，余 13 GB 给 KV cache |

**Pepper 接入不改本预算**：Pepper 机载为 x86 嵌入式级算力，只作纯客户端（麦克风/扬声器 I/O + NAOqi 动作），不本地跑 LLM/ASR/TTS（详见 ADR-002 与 `pepper/README.md`）。

**由此修正 ADR-005 §决策「30B+ 管情感/健康/安全」**：

- 30B 级 dense/MoE 量化后仍需 **17–18GB**，与 ASR + TTS 同卡必然 OOM；
- 本期（单卡 24GB）双模型路由改为：**8B 主 / 14B 高价值**；
- 30B 只在**新增第二张卡**或**迁移到 DGX Spark 独立节点**时启用（注意 ADR-005：Spark 带宽仅 4090 的 1/4，不做并发服务器，只做大模型/微调节点，通过局域网 API 接入）；
- 硬纪律：**禁止用 transformers 默认 FP16 加载 8B**（16GB，单卡即满）。一律走 Ollama / vLLM / llama.cpp 量化。

并发口径沿用 ADR-005：按**同时活跃 8–10 路**规划（30 是注册量，不是并发量）；实际同时说话远少于在线数。

## 决策 3：chassis-gateway 不部署在 4090 上

| | 说明 |
|---|---|
| **推荐（A）** | gateway 外移到常开的树莓派 5 / 工控机（¥600–1500），只要求与底盘同局域网 |
| 可接受（B） | 同机但必须是**独立容器 + `restart: always` + 独立 systemd 单元**，不与大脑共享进程 |
| 理由 | 4090 常被训练/微调占用、重启驱动、被人抢占。gateway 跟着挂 → 机器人进入**"失联但仍在动"**状态，是本系统最危险形态（30kg 移动底盘巡游中无人可喊停） |

**不变量（无论 A/B 都得有）**：gateway 与大脑/底盘的心跳中断超过 N 秒 → 自动 `softScram`。此规则写入 `safety.yaml`，不依赖人工按急停。

## 决策 4：八项隐形联网点必须清零

| # | 联网点 | 处置 |
|---|---|---|
| 1 | **TTS 默认 EdgeTTS（微软）** | 换本地 GPT-SoVITS / Index-TTS；老人音色用克隆的温和女声 |

> **实施补充（2026-10-06 核对 xiaozhi-esp32-server v0.9.7 实测）**：
> 上游 `config.yaml` **已内置本地 TTS 适配器**，第 1 项**只需改配置指向本地服务，
> 不必自己写适配器**：
> - `TTS.GPT_SOVITS_V3`（L948，`type: gpt_sovits_v3`，`url: http://127.0.0.1:9880`）
> - 另有 `GPT_SOVITS_V2`（L922）、`FishSpeech`（L900）、`CosyVoiceSiliconflow`（L863）
>
> 同理 LLM 侧**已内置 `OllamaLLM`**（L664，`type: ollama`），
> `selected_module.LLM: ChatGLMLLM`（L239）→ `OllamaLLM` **只改一个名字**即可。
>
> ⚠️ 但 `GPT_SOVITS_V3.refer_wav_path` 默认是上游示例音频 `caixukun.wav`（L956），
> **必须替换为老人场景的温和女声克隆**。
>
> 完整物料清单与下载命令见 `docs/OFFLINE-MATERIALS.md`。
| 2 | **ESP32 固件 OTA/WS 指向官方 `xiaozhi.me`** | 改本地 `http://<内网IP>:8003/xiaozhi/ota/` 与 `ws://<内网IP>:8000/xiaozhi/v1/`；WS 可用 AP 配网页改，OTA 通常需重编译——本地起 OTA 服务形成闭环，避免反复重试 |
| 3 | **天气/新闻/音乐/搜索插件走公网 API** | 禁用或改本地 mock（老人高频问天气，必须有降级话术） |
| 4 | **ESP32 无 RTC，重启时间归零** | 局域网 NTP（Windows W32Time / Linux chrony）+ DHCP option 42，或 WS hello 下发时间戳。否则闹钟、吃药提醒、记忆时间戳全崩 |
| 5 | **模型权重 / Docker 镜像需联网下载** | 首次部署**必须在有网时完成**：ModelScope/HF 权重下全、`docker save` 成 tar 导入 |
| 6 | 智控台前端构建需 npm 联网 | 离线场景直接用 server-only，不构建前端 |
| 7 | 固件内音乐拉取 / 版本检查 | 关闭 |
| 8 | **Pepper 内置云端服务 / NAOqi 遥测** | 禁用 ALSpeechRecognition/ALTextToSpeech/ALDialogue（改云端 xiaozhi + GPT-SoVITS）；关闭 NAOqi 自动更新与遥测（机箱外连 SoftBank）；预装本地中文语音包兜底；ALNavigation 地图本地建好（见 `pepper/README.md` §4）；**Pepper 开机无需联网激活已确认（用户）**，air-gapped 前置条件满足，无 SoftBank 账号激活依赖 |

## 决策 5：三级降级（4090 是单点故障）

| 级别 | 触发 | 行为 |
|---|---|---|
| L0 | 云端全挂 | 端侧离线唤醒（py-xiaozhi 自带 Sherpa-ONNX）+ 预置话术音频 |
| L1 | LLM 挂但服务在 | 关键词规则兜底 → 固定回应 + 固定动作 |
| L2 | 仅 TTS 挂 | 蜂鸣 + 动作替代语音 |

建议配 UPS（实验室断电/假期场景）。

## 验收方法

**断网测试**：把 4090 默认网关指向黑洞或防火墙阻断全部出站 → 跑一轮完整对话 → **日志里所有超时的请求就是漏网的联网点**。比逐条排查快得多。
