### 🔴 1.2 G4 · 单server 绑多本体的device_id 歧义（**新发现，建议优先**）

- **问题**：overlay X1 用的是**静态配置** `suiyue.device_id: pepper-01`。
  但 `xiaozhi-server` 是**单进程多设备**——Otto / Reachy / Pepper / 大亮
  都连同一个 server。静态配置回答的是"**这个 server 是谁**"，
  而实际需要的是"**当前这条 WS 连接是谁**"。
- **后果**：四本体共机时，Pepper 的对话会拿到 Otto 的场景包（或反之），
  且 `get_scene(device_id)` 取错包 → 注入错误 persona。
- **待决策**（需用户拍板，见 §4）：
  - 方案 a：**每本体一台 server / 一个容器**（配置最简，资源浪费）；
  - 方案 b：按 WS 握手中的客户端标识**动态识别**（需第 4 处 overlay 改动，
    且要改X1 的语义：从"静态 device_id"变成"设备标识映射表"）；
  - 方案 c：端侧在 `hello` 包里带 `device-id`（最干净，但要确认 server
    是否透传该字段给 `get_scene` 调用方）。
- **现在能做的**：读 v0.9.7 的 WS 握手与 `hello` 处理代码，确认
  **server 有没有把"连接来自哪个设备"暴露给 MCP 调用上下文**。这个答案
  决定了 a/b/c 怎么选，**且不需要 4090**。

### 🟡 1.3 意图与情绪的耦合（LLM 侧增强）

- **现状**：`get_emotion` 靠**扫描 LLM 回复里的第一个 emoji** 判定情绪。
  这意味着：**LLM 不吐 emoji → 永远 `neutral` → 永远 Stand**。
- **待做**：在场景包 prompt 里明确要求"用 emoji 表达情绪"，
  或在 X3 注入时补一段情绪标签说明。这是 X3 的**后续增强项**（不是 bug，是设计缺口）。
- **可行性**：✅ 纯 prompt 文本改动，本机可做可测。
